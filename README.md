# 88FRP Windows 原生客户端

一个面向 Windows 的 88FRP 桌面客户端，提供原生窗口、托盘后台运行、开机自启动、远程配置同步、隧道选择和日志查看。3.7.1 起统一入口会每 5 秒在后台自动检查 88FRP 节点地址，平台更换节点后无需手动同步；网页、远程桌面和 SSH 同时提供自动双栈、IPv6 专用、IPv4 专用三条线路：优先走公网 IPv6，IPv4 通过 88FRP 兜底，并用 Cloudflare 子域名区分服务。

## 主要功能

- 原生 Windows 桌面界面，双击 `88FRP.exe` 即可使用
- 统一桌面和 Web 的字体、主操作及卡片层级，修复折叠、输入与刷新记忆；默认展示隧道，配置同步按需展开
- 关闭窗口后保持托盘后台运行
- 首次启动引导设置开机自启动
- SYSTEM 开机后台任务 + 用户登录托盘任务，无需登录即可恢复隧道与域名同步
- 后台核心、主隧道和访问中心均有自动守护，网络抖动或进程异常后会持续重连
- 自动同步最低间隔为 5 分钟，遇到超时或限流时自动退避，避免频繁请求
- 旧版域名绑定在原生桌面和 Web 控制台均可配置，所有隧道（含未启用）共用域名、按端口访问
- 旧版域名绑定默认每 15 秒检查节点 IP，可设为 5–3600 秒；IP 不变不访问 Cloudflare，变化后才核对解析，失败退避重试
- 支持同步 88FRP 远程配置
- 桌面端与 Web 控制台均可连接 88FRP 账号并显示隧道备注名称
- 可选择保存加密密码，在登录失效时自动重新登录
- 现代化响应式 Web 控制台，支持手机、平板、桌面及明暗主题
- 支持只运行勾选的隧道
- 同步后保留已保存的隧道选择，新隧道默认关闭
- 按 88FRP 备注或隧道名称开头自动分组，支持整组启用/停用和手动覆盖分组
- 配置编辑、实例启动/停止/重启、运行日志查看
- 运行日志自动轮换，单份最多约 5 MB，并保留最近两份历史日志
- 高 DPI 适配，支持高分辨率屏幕
- 单设备统一入口：一台设备只管理一个设备和一组服务，不再在页面中切换多台设备
- 一个统一 HTTPS 端口（默认 `7777`）承载所有网页服务，由受管 Caddy 按域名转发
- IPv6 直连设备，IPv4 经单条 88FRP HTTP 隧道回源；浏览器和系统按 A/AAAA 自动选择
- 管理页与服务页采用成熟产品的紧凑层级：服务行式排列、独立图标与状态，打开/复制/更多操作不再堆成大卡片
- 设置页首屏不再等待日志和完整健康探测；运行记录只在展开时加载，本机实测冷启动约 0.45–0.48 秒、缓存重载 0.1 秒内
- 原生客户端默认收起手动线路，日常只保留一个统一入口；网页、远程桌面和 SSH 的三线路地址仍可随时展开复制
- 自动入口、IPv6 专用、IPv4 专用和 SSH 专用域名共用八条 Cloudflare 记录，每 5 秒检查地址变化，变化后才写 DNS
- 公开只读导航页与管理后台分离；管理后台继续使用控制台账号和密码保护
- SSH 和远程桌面都使用独立 TCP 端口，并提供自动双栈、IPv6 专用、IPv4 专用三套域名；UDP 服务也支持 IPv6 直连和 IPv4 兜底
- 统一入口的配置、DNS、Caddy、frpc、中继、防火墙和回滚操作全部写入审计日志
- 保留旧版独立访问中心和旧版兼容页，已有实例、账号、隧道选择和分组不被删除

## 下载使用

请在 GitHub Release 中下载：

```text
88FRP-Windows-Setup-3.7.1.exe
88FRP-Windows.zip
```

安装版适合需要管理员安装、开机未登录也运行的电脑；便携版解压后双击 `88FRP.exe` 即可使用，无需管理员权限。升级安装版时直接覆盖安装，不要先卸载。

覆盖升级会显示欢迎、目录选择、快捷方式与自启动选项、安装确认和完成页；安装前自动备份并保留原数据目录。

3.3.0 的统一入口是新入口，不会自动删除旧版实例数据。旧实例仍可从托盘菜单的“打开旧版兼容页”进入；确认新入口稳定后，再按自己的节奏处理旧配置。

访问中心所有可打开的地址均为超链接，包括未启用隧道的域名、自定义地址和节点直连；隧道启用状态单独显示，UDP 与纯地址模式支持复制。

3.2.4 升级会同时识别旧 Windows 服务和计划任务，先停止旧后台并备份，再检查文件是否允许替换。旧服务使用的 ProgramData 数据会保留，不会被空的 LocalAppData 设置覆盖；两个目录都有历史数据时会停止升级并提示处理，不自动合并或删除。新版后台启动验证通过后，才移除旧服务注册并将旧服务程序归档到备份。

旧版无前缀 DPAPI 凭据、SecureString 凭据和本机加密凭据均可识别；账号、访问中心、控制台会话、隧道选择和分组会保留。升级失败会恢复原服务及任务的启动状态；请直接覆盖安装，勿先卸载。

安装后从开始菜单或桌面快捷方式打开 `88FRP`。不要单独打开 `88frp-web.exe`，它是隐藏运行的后台核心。

## 单设备统一入口（3.7.0）

统一入口解决的是“很多网页服务都要各自占用一个公网端口”的问题。现在一台设备只保留一个设备根域名和一个网页入口端口，所有网页服务用子域名区分。

以下面配置为例：

```text
设备根域名：xps.liuhaobin.top
统一入口端口：7777
一个本地网页服务：alist -> 127.0.0.1:5244
```

会得到这些地址：

| 用途 | 地址 | 是否需要登录 |
| --- | --- | --- |
| 本机管理控制台 | `http://127.0.0.1:8801/gateway` | 仅本机，Windows 桌面请求可进入 |
| 公开只读导航 | `https://xps.liuhaobin.top:7777/` | 否，能打开的人都能看到服务名称和链接 |
| 统一入口管理后台 | `https://admin.xps.liuhaobin.top:7777/` | 是，使用“控制台安全”中设置的账号密码 |
| 具体网页服务 | `https://alist.xps.liuhaobin.top:7777/` | 由被代理的应用自己决定 |

根域名 `/` 对应公开导航页；`admin.` 前缀专门进入管理后台；其他子域名按服务配置转发。端口设置为 `443` 时，地址里会自动省略 `:443`，但当前默认使用 `7777`。

### 首次启用

1. 在 Windows 客户端左侧点击“统一入口”。
2. 设置设备名称、设备根域名和统一入口端口。
3. 从已有同步来源导入，或用 88FRP 同步密钥创建新的来源。旧实例数据不会被删除。
4. 在“域名与证书”页保存 Cloudflare API Token。Token 需要目标根域的 Zone DNS 编辑权限。
5. 点击“开放所需端口”添加 Windows 入站规则；程序不会关闭 Windows 防火墙。
6. 添加网页服务或 UDP 服务，确认 Caddy、frpc 和需要的中继都显示运行。
7. 先在本机打开管理后台，再到外网分别用 IPv6 网络和仅 IPv4 网络测试公开导航与服务链接。

Cloudflare Token 只在本机加密保存，Caddy 通过子进程环境变量取得，不写入 `Caddyfile`。不要把 Token、FRP 密钥或账号密码写入导航页的服务说明。

### IPv4 和 IPv6 怎么分流

同一设备根域名维护八条 Cloudflare 记录：

| 记录 | 内容 | 作用 |
| --- | --- | --- |
| 根域 A | 88FRP 节点 IPv4 | IPv4 兜底 |
| 根域 AAAA | 本机当前公网 IPv6 | IPv6 直连 |
| `*.` 通配 A | 88FRP 节点 IPv4 | 所有子域名的 IPv4 兜底 |
| `*.` 通配 AAAA | 本机当前公网 IPv6 | 所有子域名的 IPv6 直连 |
| `v4.` A | 88FRP 节点 IPv4 | 强制 IPv4 网页与远程桌面入口 |
| `v6.` AAAA | 本机当前公网 IPv6 | 强制 IPv6 网页与远程桌面入口 |
| `ssh-v4.` A | 88FRP 节点 IPv4 | 强制 IPv4 的 SSH 入口 |
| `ssh-v6.` AAAA | 本机当前公网 IPv6 | 强制 IPv6 的 SSH 入口 |

因此自动入口同时有 A 和 AAAA；专用域名只保留对应地址族。支持 IPv6 的浏览器/系统会优先尝试自动入口的 IPv6；需要诊断或强制线路时，可以直接使用 `v6.` / `v4.` 网页入口、远程桌面和 SSH 地址。网页和 SSH 都是 TCP，可以这样双栈；UDP 由客户端自身选择可用的地址族。

实际链路是：

```text
IPv6 客户端 -> 设备公网 IPv6:7777 -> Caddy -> 本机服务
IPv4 客户端 -> 88FRP 节点 IPv4:7777 -> frpc 单条 HTTP 隧道 -> 本机 127.0.0.1:7777 -> Caddy -> 本机服务
IPv6 专用入口 -> https://v6.设备根域名:7777 -> 设备公网 IPv6 -> Caddy -> 本机服务
IPv4 专用入口 -> https://v4.设备根域名:7777 -> 88FRP 节点 IPv4 -> 本机 Caddy -> 本机服务
```

这里要区分两个概念：

- IPv6 地址通常是“一台设备一个全球地址”，所以 AAAA 指向的是当前这台设备的公网 IPv6。
- IPv4 公网地址通常是 88FRP 节点共享的地址，多台设备靠不同的公网映射端口区分。因此同一个 88FRP 服务器上的不同设备不能同时占用同一个统一入口端口；例如设备 A 用 `7777`，设备 B 要改用另一个端口。每台设备仍可使用自己的根域名和通配子域。

程序每 5 秒检查一次 88FRP 来源配置、节点 IPv4、本机 IPv6、域名和绑定目标。地址不变时不会调用 Cloudflare 写入接口；变化后才更新全部 AAAA/A。DNS TTL 最低 60 秒，因此“检查频率是 5 秒”不等于远端缓存立刻刷新。程序只会清理同时匹配本机账本、精确托管备注和域名范围的旧记录，不会删除手工创建的 A、AAAA 或 CNAME。

如果本机没有公网 IPv6，管理页会给出提示，AAAA 不会被伪造；IPv4 入口仍可工作。反过来，如果只使用 IPv6 直连而 IPv6 被运营商、光猫或 Windows 防火墙拦截，IPv4 也不会自动穿越所有网络限制，需要同时检查每一层防火墙。

### SSH、RDP 和 UDP

- SSH 使用一个公网端口，三条地址分别是 `ssh.<设备根域名>:<端口>`、`ssh-v6.<设备根域名>:<端口>`、`ssh-v4.<设备根域名>:<端口>`。自动地址按网络能力选路，后两条用于强制 IPv6 或 IPv4。
- RDP 不把本机 `3389` 直接暴露到公网，而是经本机同端口中继和 88FRP TCP 直通端口访问，例如 `xps.liuhaobin.top:64540`；专用地址为 `v6.xps.liuhaobin.top:64540` 和 `v4.xps.liuhaobin.top:64540`，不依赖 SSH 隧道。
- 公开导航页的“远程访问”区会分别列出 SSH 和远程桌面的自动、IPv6 专用、IPv4 专用地址，可逐条复制。
- UDP 服务各自使用一个公网端口；IPv6 客户端直连设备，IPv4 客户端走 88FRP。程序用本机同端口中继把两条路径汇合到真实 UDP 端口，因此不需要两套服务配置。
- 公网端口和本地端口相同时，中继会尽量复用现有监听；如果应用只监听 IPv4，建议改用不同的公网端口，避免占用冲突。

### 防火墙与排障顺序

统一入口需要同时检查四层：

1. 88FRP 节点/服务端是否放行对应的公网端口。
2. 家用路由器或光猫是否放行设备的公网 IPv6 TCP/UDP 端口。
3. Windows 防火墙是否允许 `Caddy`、`88frpc` 和本机中继所需的 TCP/UDP 端口。
4. 本机服务是否监听在管理页填写的 `本地地址:本地端口`。

“开放所需端口”只添加受管入站规则，不会关闭整个 Windows 防火墙。光猫或路由器如果没有 IPv6 防火墙开关，应该添加入站允许规则，或按设备厂商的安全设置放行指定端口；不建议长期整机暴露所有端口。

### 运行日志

默认数据目录是 `%LOCALAPPDATA%\88frp-node\data`；安装版以安装目录 `machine-config.json` 记录的数据目录为准。统一入口相关文件在 `gateway` 子目录：

```text
gateway/audit.log               配置变更、DNS、进程、中继、防火墙和回滚审计
gateway/logs/caddy.log          Caddy 输出
gateway/logs/caddy-access.log   Caddy 访问日志
gateway/logs/frpc.log           统一 frpc 输出
gateway/runtime.json            当前进程和调度状态
gateway/state.json              设备、服务、域名和 DNS 账本
gateway/Caddyfile               Caddy 当前配置
gateway/frpc.toml               统一 frpc 配置（含鉴权，禁止外传）
app.log                         应用总日志
```

排查时先看 `gateway/audit.log` 的时间线，再看对应进程日志。审计记录中的 Token、密码和授权头会脱敏，但整个数据目录仍应当作私密数据保存。

## 88FRP 账号与备注名称

在桌面端或 Web 控制台点击“连接 88FRP”，输入 88FRP 用户名和密码即可。

- 连接完成后会获取已有隧道的官方备注名称
- 同步配置发生变化时自动更新备注名称
- Web 隧道列表优先显示备注名称，并保留 FRPC 标识和端口信息
- 默认使用 Windows DPAPI 加密保存密码；取消勾选后，只保存登录令牌，不会自动重新登录

## 隧道选择逻辑

客户端会保存远程同步得到的完整配置，但实际运行时只生成包含已勾选隧道的运行配置。

- 完整配置：`frpc.toml`
- 隧道选择：`selection.json`
- 手动分组覆盖：`tunnel-groups.json`
- 实际运行配置：`runtime-frpc.toml`

同步远程配置后：

- 已存在隧道保留原来的启用/禁用状态
- 新出现的隧道默认关闭
- 未勾选隧道保留在配置中，但不会启动
- 名称含有 `-`、`_`、空格、`/`、`:` 等分隔符时，分隔符前内容会作为自动分组；没有分隔符时，会合并名称开头相同的隧道
- 例如“公司电脑”和“公司 alist”会自动归入“公司”；在隧道列表的“分组”输入框填写内容后，会优先使用手动分组，并在后续同步后保留

## 旧版独立访问中心（兼容模式）

统一入口启用后，桌面端主入口会变为“统一入口”；旧版访问中心仍可从托盘菜单的“打开旧版兼容页”进入，用于保留原有实例和设置。它适合把自己的 FRP 服务器作为一个固定入口使用：

1. 填写该 FRP 服务器地址、服务端口、分配给访问中心的公网端口和 Token。
2. 访问中心始终以公开只读模式启动，不设访问密码。
3. 客户端会在本机 `127.0.0.1:8802` 启动只读页面，并用一条独立 FRP 连接映射到固定公网地址。

访问中心会实时读取现有实例的同步配置、已保存的 88FRP 备注名称和启用状态；它不会修改原来的 88FRP 配置、隧道选择或运行进程。

- 所有 TCP 隧道默认生成可直接打开的 HTTP 链接
- UDP、STCP、SUDP、XTCP 会按实际协议展示，不能直接打开的不会伪造网页链接
- 访问链接本身可直接点击，在浏览器新标签页打开
- 按同步备注或隧道名称开头分组展示，每个分类可折叠；折叠状态会保存在当前浏览器
- 访问中心允许查看、复制和打开链接，但不会允许从公网修改链接设置
- FRP Token 使用本机 DPAPI 加密保存，不会从状态接口或页面返回
- 访问中心内置自定义服务器真实通道测速：默认 10 秒，显示延迟、当前/平均/峰值下载速度与已传输数据；测速不使用 88FRP 官方线路，不新增公网端口

任何知道固定地址的人都能看到隧道名称和访问链接，适合可信网络或不敏感的服务。访问中心通过 HTTP 提供时，建议仅在可信网络使用；要获得完整的传输抗篡改能力，需要让该入口具备可信 HTTPS。

## 统一入口管理后台与旧版控制台安全登录

统一入口的 `admin.<设备根域名>` 管理后台和旧版 88FRP 控制台共用同一套控制台安全设置，但管理员账号与 88FRP 官方账号相互独立。首次在 Windows 客户端打开后，在“全局设置 → 控制台安全”设置管理员账号和密码；密码不会以明文保存。

- 普通登录的有效期为 24 小时；勾选“记住此设备”后，会话会持续有效，直到主动退出、在 Windows 客户端撤销会话、修改密码或清理浏览器数据。
- 密码校验采用 PBKDF2 派生、一次性挑战响应和 HTTP-only 会话 Cookie；本机保存的校验信息使用本机 DPAPI 保护。
- 为避免在不安全网络中传输登录凭据，远程浏览器登录需要可信 HTTPS；`127.0.0.1` 本机访问可正常登录。旧版访问中心维持无密码只读，不受此设置影响。

## 自启动原理

安装时可选择开机自启，之后也可在原生客户端“设置 → 后台运行”中开关（需要管理员权限）。

- `88FRP Backend`：SYSTEM 身份，开机后延迟 45 秒运行隐藏后台，不需要登录；启动失败后每分钟重试。
- `88FRP Desktop`：当前用户登录后显示托盘入口，连接已经运行的后台。
- 旧登录任务及注册表启动项会清理，不再叠加启动。

安装器保留原来的数据目录，路径记在安装目录的 `machine-config.json`。旧账号、控制台验证信息、访问中心和 Cloudflare 的加密凭据会在安装时迁移为本机 DPAPI，原密文备份保存在数据目录的 `credential-backups`；目录权限限于所属用户、SYSTEM 和管理员。若使用其他 Windows 账号安装而无法解密旧凭据，安装会明确提示失败并保留数据。

## 旧版域名绑定（兼容模式）

统一入口使用自己的“域名与证书”页，不建议再为统一入口服务配置旧版域名绑定。旧版“域名绑定”页仍保留，供原来的多实例/特殊场景使用。

在旧版“域名绑定”页授权 Cloudflare Token，开启“启用域名绑定”，并在负责维护 DNS 的一台设备上打开“由本机修改解析”。其他设备保持只读。

- “自动跟随节点 IP”默认每 15 秒检查，可在桌面与 Web 域名页调整为 5–3600 秒；IP 不变不请求 Cloudflare，IP 或绑定目标变化后才核对并按需写入。首次启动与手动同步仍核对一次。
- IP 检查频率与 DNS 缓存 TTL 独立；缓存过期前部分设备可能继续使用旧 IP。
- 访问中心并列展示域名链接与节点直连，各自支持复制和打开；保留自定义链接，未启用隧道仍可查看和复制地址。
- 只读模式下，预览、授权验证及同步均不发送 DNS 写请求。
- 所有隧道共用一条灰云 A 记录，未启用隧道仍显示访问地址；它们需要在面板启用后才可连接。
- 预览只读取 Cloudflare；同步不会覆盖手工 A / AAAA / CNAME。TXT 可与 A 记录共存。
- 删除部分隧道保留共享记录；不再需要的旧记录只在“本机账本 + 精确托管备注”均匹配时清理。
- 界面显示自动检查状态、最后检查和错误信息；网络失败、限流和授权失效均有提示与后台重试。

## 卸载

卸载会先停止后台和受管隧道，并清理两个计划任务和历史启动项。默认保留数据（静默卸载也保留）；交互卸载时明确选择“否”才删除原用户目录中的数据。升级请直接覆盖安装，不要先卸载。

## 常见问题

### 为什么同步配置提示 500？

这通常表示远程配置接口返回错误。常见原因：

- 密钥不正确
- 88FRP 平台接口临时异常
- 当前账号没有返回有效配置

请检查密钥后再同步。

### 为什么不建议单独打开 88frp-web.exe？

`88frp-web.exe` 是后台核心，不是用户入口。普通用户应该打开 `88FRP.exe`。

### 这是 Windows Service 吗？

后台使用 SYSTEM 开机计划任务，无需用户登录；用户登录后单独启动原生托盘客户端。没有额外注册 Windows Service。
