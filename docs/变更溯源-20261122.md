## 2. 本轮目标

把原有“多实例 + 每服务独立公网端口”的控制台，重构为“一台设备一个 App”的统一入口：

1. 本地不再展示可切换的设备列表；一个 App 固定服务一台设备。
2. 所有网页服务共用一个公网端口，例如 `7777`。
3. 用子域名区分服务，例如 `alist.xps.example.com:7777`。
4. IPv6 直连设备公网地址；IPv4 自动经 88FRP 节点回到同一设备端口。
5. Caddy 作为受管子进程，负责 TLS、Host 路由和导航入口。
6. SSH 单独保留一个映射端口；RDP 通过 SSH 隧道访问；UDP 按服务独立映射端口。
7. 每 5 秒检查节点 IPv4、本机公网 IPv6 和配置变化；地址未变化时不写 Cloudflare。
8. 所有配置变更、DNS 写入、进程启动/停止、防火墙调整和失败恢复写入审计日志。

## 3. 访问链路

```text
IPv6 浏览器
  -> [设备公网 IPv6]:7777
  -> Caddy（双栈监听）
  -> 按 Host 转发到 127.0.0.1:<服务端口>

IPv4 浏览器
  -> [88FRP 节点 IPv4]:7777
  -> frpc 单一 HTTP 隧道
  -> 127.0.0.1:7777
  -> Caddy（同样按 Host 转发）
```

同一设备域名只维护四条 DNS：

- 根域名 A -> 88FRP 节点 IPv4
- 根域名 AAAA -> 设备当前公网 IPv6
- 通配 `*.` A -> 88FRP 节点 IPv4
- 通配 `*.` AAAA -> 设备当前公网 IPv6

普通网页服务不再创建精确 A/AAAA，避免覆盖通配记录。

## 13. 2026-11-23 · 网页、远程桌面和 SSH 三线路交付（3.5.0）

### 原因

同一个域名可以同时有 A 和 AAAA，由操作系统按网络能力自动选择，但无法在 URL 中强制“只走 IPv6”或“只走 IPv4”。用户需要保留自动双栈入口，同时为诊断、强制线路和故障兜底提供明确可复制的专用地址，因此网页、远程桌面和 SSH 都拆成三套入口：

- 自动：同一域名同时具备 A/AAAA，按当前网络自动选路。
- IPv6 专用：专用子域只发布 AAAA。
- IPv4 专用：专用子域只发布 A，并继续经 88FRP 节点回源。

### 当前地址模型

以实际配置 `xps.liuhaobin.top`、统一入口端口 `7777` 为例：

| 服务 | 自动 | IPv6 专用 | IPv4 专用 |
| --- | --- | --- | --- |
| 网页 | `https://xps.liuhaobin.top:7777` | `https://v6.xps.liuhaobin.top:7777` | `https://v4.xps.liuhaobin.top:7777` |
| 远程桌面 | `xps.liuhaobin.top:64540` | `v6.xps.liuhaobin.top:64540` | `v4.xps.liuhaobin.top:64540` |
| SSH | `ssh.xps.liuhaobin.top:50258` | `ssh-v6.xps.liuhaobin.top:50258` | `ssh-v4.xps.liuhaobin.top:50258` |

这些地址由同一份网关状态生成，网页后台、公开导航页和 Windows 客户端不再各自拼接字符串。
