## 5. 已覆盖的关键行为

- 根域与通配 A/AAAA 四记录生成，手工记录不被覆盖或误删。
- Caddy `adapt` 预检不访问 Cloudflare，启动失败会恢复上一版配置。
- 网页服务修改与 DNS 同步失败可回滚，不会留下空状态。
- SSH/UDP 中继支持 TCP/UDP 回环、双栈监听和主动断开长连接。
- 未登录管理 API 拒绝访问；公网伪造 `X-88FRP-Desktop` 不能绕过登录。
- 后台退出停止 Caddy/frpc/中继并释放锁。
- 旧实例迁移失败时恢复旧运行状态，不把设备卡在不可用状态。
- Caddy 实际版本为 `v2.11.9`，模块列表包含 `dns.providers.cloudflare`；生成的示例 Caddyfile 经实际 `caddy adapt` 校验通过。
- 生成的示例统一 frpc 配置经实际 `88frpc verify -c` 校验通过。
- 原子配置替换在 Windows 短时占用时会进行渐进重试，并有模拟 12 次 `EPERM` 的回归测试。

## 6. 尚需人工确认

- 在真实光猫/路由器上放行 IPv6 TCP/UDP 入站。
- 在真实 Cloudflare zone 上首次申请通配证书并确认 DNS-only 记录。
- 在只有 IPv4 的手机流量和同时支持双栈的 Wi-Fi 上分别访问公开导航与服务。
- 确认同一 88FRP 服务器上多台设备使用不同统一入口端口。
- 确认 Windows 防火墙规则、88FRP 服务端端口和本机应用监听三者一致。
- 安装到真实目录前，先备份 `machine-config.json` 指向的数据目录。

## 7. 结论

源码、测试、构建、隔离烟测和真实覆盖安装满足本轮发布前条件。公网链路和 Docker 容器运行尚未在本机完成真实验证，不能把这两项标记为“已验证”。
