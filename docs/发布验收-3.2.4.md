# 3.2.4 安装升级与旧服务清理验收

日期：2026-10-17。

## 根因

旧安装器仅暂停已知计划任务，没有识别 Windows 服务启动的旧后台。服务仍能重新拉起后台，造成程序文件占用；预检只看进程名，没有验证文件的替换权限。升级也只读取默认用户目录或原 machine-config，未识别旧服务的 ProgramData 数据，因此可能备份、迁移了空目录。旧服务的无前缀 DPAPI 凭据被当成 SecureString，访问中心和账号会解密失败。

## 修复

- 使用同一升级事务记录原服务启动方式、运行状态、真实数据目录和备份位置。
- 仅处理当前安装目录及同一产品既有安装目录内的旧服务和程序，不结束其他位置的同名程序。
- 先禁用旧服务以防止重新拉起，安全停止后台并保留实例恢复标记，再检查文件的写入、删除权限及只读属性。
- 优先保留已有数据；识别旧服务真实使用的目录。两份目录都有历史配置时停止升级，不自动覆盖、合并或删除。
- 迁移前完整备份配置、账号、会话、选择、分组、日志及界面偏好，备份仅允许原用户、SYSTEM 和管理员访问。
- 兼容无前缀 DPAPI Base64、旧 SecureString 与 machine: 凭据；全部解密成功后才写入。
- 新后台通过健康检查及进程归属核对后，删除旧服务注册，将旧服务程序保存在备份中；预检或配置失败则恢复原服务和任务状态。
- 未勾选开机启动时，也会运行并验证本次后台，验证后仍保持开机任务禁用。

## 验证

| 项目 | 结果 |
|---|---|
| 自动测试 | 84 项：83 通过，1 项按平台预期跳过，0 失败 |
| 真实 Windows 服务 | 独立测试服务运行并占用程序文件；预检拦截、停止、回滚恢复、再次升级后删除注册并归档程序均通过 |
| 真实禁用任务 | 临时启用以运行本次后台后恢复禁用，任务实际执行成功且最终仍禁用 |
| 测试隔离 | 独立服务测试前后，实际后台进程及原配置保持不变 |
| 数据冲突 | 两份历史实例目录同时存在时中止，双方原文件均保留 |
| 文件预检 | 实际只读文件与独占句柄阻止安装，原文件不被替换 |
| 凭据兼容 | 真实 Windows DPAPI 生成的旧服务凭据可读取、可迁移，保留其他字段 |
| 覆盖升级 | 实际公司电脑从 3.2.3 覆盖到 3.2.4，安装器返回 0，7 个已安装文件哈希与交付包一致 |
| 历史数据 | 原数据目录与所有者保持不变；配置、选择、分组、标签哈希及域名选项一致，20 条隧道、10 条启用全部保留 |
| 实际运行 | 实例、访问中心及两项后台/桌面任务均运行；后台只有一份，旧服务注册及原服务程序已移除，旧程序已归档至完整备份 |
| 开机配置 | SYSTEM BootTrigger 和用户 LogonTrigger 均启用且实际启动正常；未进行整机重启 |
| 公网入口 | 刷新实际访问中心后显示 3.2.4、已连接、10/20 条隧道，同时保留域名与节点直连地址 |
